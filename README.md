# CryptoQuantPipeline

Binance USDT 永续合约的横截面选币策略。332 个因子、LightGBM 四头模型，每晚出次日预测和交易计划。

> **管线状态（2026-09-21 定稿）**：305 因子 + 按头特征策略（selection 策展池 236 特征直入、
> timing/range 走 IC 筛选）+ 按头调优超参。wf_step=10 正式验证：selection RankIC **+0.0212
> (t=+2.49)**，timing Brier **0.258**（历史最好），range 保形后覆盖 **90.6%/11.0%**（pinball
> 均优于 158 版本）。策略回测 +176%（Sharpe 1.03），但**策略层总收益噪声极大**（同等信号
> 质量下不同配置给过 +56%~+176%），可信的是模型层指标和相对结论。
> **2026-09-21 追加**：selection 换 5 模型 bagging 集成（挤掉种子运气）、每天限买 3 个、
> 空位持现金；集成均值排名 +132%（Sharpe 0.92）。置信度(t-stat)排名经完整消融后
> **不采纳**——模型层更好但排序不粘、策略层大幅变差，细节见[集成实验](#集成--限买实验2026-09-21wf10-重放消融)。
> 中途试过的两条弯路已记录在案：全 305 直入会稀释 RankIC 至 0，单变量 IC 筛选/L1 路径
> 用在 selection 上会杀死排序信号——细节见 [按头特征策略](#模型层--按头特征策略)。

> 必读：[择时层为什么默认关闭](#为什么择时闸门默认关闭) 和 [已知局限](#已知局限)。

## 架构

```
   Binance fapi (永续) + api (现货)
            │
            ├─ 永续日 K：OHLCV + 成交额 + 笔数 + 主动买入量
            ├─ 资金费率：8h 结算 → 按 UTC 日聚合
            └─ 现货日 K：只为算基差
            ▼
   data/binance/{SYMBOL}.parquet        44 个币 × ~1095 天
            ▼
   factors.compute_factors()            248 个单币因子
   factors.add_cross_sectional()      + 84 个横截面/市场/领导币因子
            ▼                          ═══ 332 个特征 ═══
   factors.add_labels()                 7 个标签（含扣资金费的净收益）
            ▼
   ┌──────────────┬──────────────┬──────────────┬──────────────┐
   │  selection   │   timing     │  range_high  │  range_low   │
   │  回归/7日收益 │ 二分类/涨跌   │ 分位数 q90   │ 分位数 q10   │
   │  embargo 7   │  embargo 1   │  embargo 1   │  embargo 1   │
   └──────┬───────┴──────┬───────┴──────┬───────┴──────┬───────┘
          │              │              └──── 保形校准 ────┘
          ▼              ▼                     ▼
      横截面排名      P(次日涨)          次日最高/最低价区间
          │
          ▼  5 模型 bagging 集成 → 均值排名（分歧度作为风险列输出）
          ▼  迟滞规则：进 top 8，跌出 top 16 才卖；每天最多新买 3 个
      各 12.5% 建仓(未满仓持现金) → output/plans/plan_YYYY-MM-DD.csv
```

### 三条设计原则

**1. 按日采样 + embargo**
所有标签都在日频网格上采样。7 日标签在相邻行之间重叠 6 天，所以每个 walk-forward
切分都留 `embargo = horizon` 的隔离带。调低 embargo 唯一的效果是让分数虚高。

**2. 永续口径，资金费计入 PnL**
做多永续在资金费为正时要付钱。按 Binance 默认 0.01%/8h 算，一年约 11% 的损耗——
大到不能忽略。回测按实际持仓逐日扣。（有意思的是选币模型倾向于挑**负资金费**的币，
默认策略的资金费是 **-3.06%**，即净收入。）

**3. 从不填充缺失值**
没有 `bfill`，没有插值。因子的滚动预热期直接丢弃（每币前 90 行），长窗口因子保持 NaN。
LightGBM 原生处理 NaN，而 NaN 在这里诚实地表示"当时还观测不到"。

## 四个模型头

| 头 | 任务 | 标签 | 输出 | Walk-forward 表现 |
|---|---|---|---|---|
| `selection` | 回归 | 未来 7 日收益 | 选币分数 | **RankIC +0.0225 (t=+2.80)** |
| `timing` | 二分类 | 次日是否上涨 | **P(次日涨)** | AUC 0.522，Brier 0.274 |
| `range_high` | 分位数 q90 | 次日最高/今收 − 1 | **次日最高价** | 覆盖率 **90.4%**（目标 90%）|
| `range_low` | 分位数 q10 | 次日最低/今收 − 1 | **次日最低价** | 覆盖率 **10.5%**（目标 10%）|

### 市场层预测（第五个头，2026-09-22 新增）

`market` 头用 BTC/ETH 领导币状态 + `mkt_*` 聚合特征（每天一行，~1000 样本，
7 叶极小树）预测**全市场（44 币等权）明日是否收涨**，夜报顶部输出一行
`Market: P(up tomorrow) = XX%`。

**必须知道的真相**：walk-forward 显示原始概率在尾部**反向失准**（预测 <40% 的
日子实际上涨 52.7%），因此加了 Platt 校准（与 range 头的保形校准同哲学）。
校准后的 Brier 0.2497 与「永远预测基准率 51%」的 0.2499 几乎相同——
**日频市场方向在这套特征下基本不可预测**，校准把输出压缩到 47.8%~54.9% 的
诚实区间。把它当**弱风险信息**用（>53% 略偏多、<48% 略偏空），不要当开关——
这和币级 timing 闸门被证伪是同一个教训。

### 周度 regime 级联（2026-09-23 新增，仅供参考、不参与交易）

按「周一定调 → 条件推荐 3 币 → 次日区间」的级联流程实现：`regime` 头**每周一**
用 BTC/ETH/SOL 状态预测未来 7 天全市场涨跌（周一到周一标签不重叠，样本独立），
立场整周固定；多头立场推 P(7 日涨) 最高的 3 个币（来自 selection 集成分歧度的
正态近似），空头立场列 P(7 日跌) 最高的 3 个，均附次日保形价格区间。

**验证结论（必读）**：63 个独立周上 AUC **0.48**、校准后 Brier 与基准率恒定预测
无差——**周度市场方向同样没有可检测的信号**（与日频市场头、币级 timing 一致，
这是本管线第三次得到同一结论）。用「阈值=基准率」重放的级联变体在本窗口出现过
Sharpe 0.9 的好看数字，但其门控符号与阈值都是在同一批 63 周上选出的，
**按噪声开采处理，不采信**。级联块保留在夜报中仅供参考（stance 对比基准率、
±2pp 内报 NEUTRAL），交易路径仍是验证过的迟滞策略；空头列表明确标注
"informational（做空回测净亏损）"。等真实运行积累到 100+ 个周一再复检。

### 概率是校准过的

`timing` 头的平均预测概率 0.489，样本实际上涨频率 0.483——**不过度自信**。
Brier 分数和 log-loss 都在监控这一点。AUC 0.522 说明排序能力很弱，但概率数值本身是可信的。

### 价格区间用了保形校准

纯分位数回归在金融数据上**系统性覆盖不足**：它在滚动窗口上拟合，波动率一扩张，
实际高低点就冲破预测区间。原始覆盖率 high 84.5% / low 18.6%，都偏窄。

加了保形修正（CQR）后：**high 90.4% / low 10.5%**，基本命中名义水平。
修正量存在模型 bundle 里，推理时自动应用。

## 为什么择时闸门默认关闭

你要的「每日择时预测」已经交付了——`P(次日涨)` 对每个币都输出，而且是校准过的。
但**拿它当每日开关会把策略打崩**：

| 策略 | 总收益 | Sharpe | 日均换手 | 手续费拖累 |
|---|---|---|---|---|
| 选币 + 迟滞（默认） | **+85.9%** | **+0.78** | 0.26 | 19.0% |
| 选币 + 日频调仓 | +105.8% | +0.85 | 0.61 | 44.8% |
| **选币 + P(up) 闸门** | **−2.3%** | +0.39 | 0.97 | 71.8% |
| 只用 P(up) 选币 | −54.3% | −0.15 | 1.14 | 84.5% |

原因不是概率没用，是**用错了地方**。看 walk-forward 全样本：

```
选币 top8 的次日收益   中位数 -0.10%   均值 +0.24%   偏度 +3.12
```

**选币层的优势在右尾，不在胜率。** top8 的次日上涨频率只有 48.5%——大多数日子小跌，
少数日子大涨。按 P(up) 分档更直白：

```
P(up) 分档      样本数    次日平均收益
  < 45%         2233       +0.18%
  45-50%         629       +0.17%
  50-55%         633       −0.03%     ← 概率更高，收益反而更差
  > 55%         2417       +0.38%
```

概率和期望收益在这里**几乎正交**。闸门筛掉的是「赢的频率低但赔率高」的票，
同时把换手从 0.26 推到 0.97，手续费翻了近四倍。

**所以**：`USE_TIMING_GATE = False`。概率作为**风险信息**输出在计划里（这个币明天大概率跌，
但期望收益为正，意味着它是高偏度的），而不是作为开关。

要打开：`python main.py nightly --timing-gate`，回测数字在上表里。

### 横截面与市场因子（84）

`cs_rank_*`（**30** 个关键因子的每日百分位排名，覆盖动量谱、风险调整动量、流动性、资金费、基差、回撤）、
`cs_z_*`（8 个）、`mkt_*`（市场收益/波动/资金费/宽度/离散度/主动买卖/基差，**14** 个）、
`exc_ret_*`（超额于市场均值，3 个）、`rel_ret_*_vs_bench`（相对 BTC，**4** 个）、
`beta_bench_*` / `corr_bench_*`（4 个）、`idio_vol_30d`。

**领导币特征（16，2026-09-22 新增，已验证）**：BTC 和 ETH 主导市场——每币与 ETH 的
30 日滚动相关 `corr_eth_30d`（与 BTC 的即 `corr_bench_30d`）、阵营谱
`lead_corr_spread_30d`（corr_BTC − corr_ETH，单变量 IC +0.021，16 个里最强）、
相对 ETH 强度 `rel_ret_{7,30}d_vs_eth`，以及两个领导币自身状态按日广播：
`{btc,eth}_{ret_7d, ret_30d, vol_14d, rsi_14d, funding_mean_7d, sma_ratio_50d}`
（按日广播的特征横截面 IC 无定义，靠树的交互项起作用）。

消融（selection 头，集成均值）：wf40 +0.0309 → **+0.0346 (t=4.00)**；
wf10 终审 +0.0184 → **+0.0206 (t=+2.38)**。两个口径都是正贡献，纳入策展池
（236 → 252 特征）。

**龙头/箱体突破特征（11，2026-09-22 新增，已验证）**：箱体突破 7 个（见 C 族）+
龙头识别 4 个——`lead_freq_30d`（30 日内进当日涨幅前 1/4 的频率）、
`down_mkt_alpha_30d`（市场下跌日的超额收益，抗跌性）、
`cs_rank_breakout_up_20d` / `cs_rank_box_squeeze_20d`（谁先突破、谁的箱体最窄）。

单变量 IC 是**全库新高**：`down_mkt_alpha_30d` **+0.089**（最强单因子）、
`breakout_up_55d` +0.068、`breakout_up_20d` +0.056；箱体宽度为负 IC
（−0.07~−0.08，宽箱=坏、窄箱蓄势=好），与形态学直觉一致。

消融（selection 头，集成均值）：wf40 +0.0346 → **+0.0405 (t=4.64)**；
wf10 终审 +0.0206 → **+0.0259 (t=+2.95)**——会话内 selection 的最好成绩。
纳入策展池（252 → 263 特征）。

横截面因子是排序模型真正需要的——一个孤立的动量值说不出这个币今天是不是最强的。

### ⚠️ 特征数量与信号质量的权衡

扩到 305 后的初步对照（同一面板、wf_step=40、19 折）：

| 特征集 | selection RankIC | t 值 |
|---|---|---|
| 158（旧） | **+0.0306** | **+4.03** |
| 305（默认超参） | +0.0027 | +0.34 |
| 305（colsample 0.3） | +0.0112 | +1.43 |
| 305（去掉新增市场级特征） | +0.0125 | +1.63 |

新特征让 MSE 变好（0.0360→0.0342）但 RankIC 变差——模型把容量花在预测市场
水平项上，牺牲了横截面排序。尝试过的正则化（colsample 0.2-0.3、min_child_samples
100-150、更小的树）都只能部分恢复。**结论：因子库越大不等于信号越强**，用之前
必须跑 `main.py backtest` 完整验证，且值得做按头特征筛选（比如 selection 头只喂
横截面与相对特征）。

### 合约因子的历史深度问题（双轨）

Binance 对这几个端点**只给 30 天历史**，无法回测：

```
openInterestHist / topLongShortAccountRatio /
topLongShortPositionRatio / globalLongShortAccountRatio / takerlongshortRatio
```

处理方式是**双轨**：

- **轨道一（进模型）**：全历史的合约因子——资金费率、基差、主动买卖不平衡、笔数。
  这些覆盖了持仓量想表达的大部分信息，而且今天就能回测。
- **轨道二（攒历史）**：`collect_short_history()` 每晚把当前 30 天窗口并进
  `data/short_history.parquet`，按 `[date, symbol, metric]` 去重。
  跑几个月后历史够了，再把它们接进因子层。

夜跑默认带上轨道二（`--no-collect-short` 可关）。

## 数据层

| 数据 | 端点 | 历史深度 |
|---|---|---|
| 永续日 K | `fapi/v1/klines` | 全历史 ✓ |
| 现货日 K（算基差）| `api/v3/klines` | 全历史 ✓ |
| 资金费率 | `fapi/v1/fundingRate` | 全历史 ✓ |
| 持仓量、多空比 | `futures/data/*` | **仅 30 天** ✗ |

### 三个运维保护

1. **下载失败绝不覆盖缓存**。每个币的数据先校验（非空、列齐、收盘价非全 NaN、
   日历覆盖率 ≥80%），失败重试 3 次指数退避，仍失败就抛 `BinanceError` 且一个字节都不写。
   写盘走临时文件 + `os.replace` 原子替换。
2. **自动剔除未收盘的当天 bar**。永续 24 小时交易，UTC 午夜前抓到的今日 bar 是残缺的
   （OHLC 不完整、资金费只结算了 1-2 次）。`drop_incomplete=True` 直接丢掉。
3. **现货端点 limit 上限是 1000**（合约是 1500）。传 1500 会静默截断分页并在序列里留洞。

| `main.py backtest` | 完整 walk-forward + 消融表 + 保形校准 | **~6 分钟** |
| `main.py full` | backtest + 今晚计划 | ~7 分钟 |
| `main.py download` | 只下载数据 | ~10 分钟 |
| `main.py tune` | 每头随机搜索超参（`--trials`、`--heads` 可选） | ~20 分钟 |

**为什么分开**：多一天数据对 walk-forward 验证的边际价值接近零，所以慢路径每周跑一次；
但分位数头需要验证过的 walk-forward 来做保形校准，`nightly` 会复用上次 `backtest` 存进
bundle 的校准量。

### 检查清单（按顺序）

**① 下载是否成功**
```
BinanceError: No symbol downloaded successfully; cache untouched.
```
限流或网络问题。缓存完好，隔一小时重跑。个别币失败会在末尾列出并跳过，不影响其余。

**② as-of 日期对不对**
```
as of 2026-09-19 (UTC bar close) | 44 symbols | 305 features
```
应该是**昨天**（UTC）。如果是前天，说明你跑早了（UTC 午夜前）。

**③ 保形校准还在不在**
```
Range calibration    high 90.4%/90%, low 10.5%/10%
```
显示 `not calibrated (run backtest)` 说明还没跑过 `backtest`，价格区间会系统性偏窄。

**④ 次日预测表** ← 你要的三个输出都在这
```
 Rank  Symbol    Close  P(up)   Exp7d      Low      High  Band  Decision
    1 ONEUSDT 0.003936  30.4% +23.44%  0.002868  0.006568 94.0%  ENTER
    5 BNBUSDT   762.52  68.5% +12.80%   733.536   824.502 11.9%  ENTER
```
- `P(up)`：次日收涨概率（校准过）
- `Exp7d`：未来 7 日期望收益（选币分数）
- `Low`/`High`：次日最低/最高价的 80% 预测区间
- `Band`：区间宽度，是很好的波动率代理

**⑤ 订单清单** ← 要执行的东西

`Ref_Price` 是信号生成时的参考价，不是成交价。滑点自负。

### 关键前提：计划文件代表你的真实持仓

**迟滞规则是路径依赖的**——今晚持什么，取决于昨晚持什么。代码从上一份计划 CSV
读当前持仓。所以：

- **没执行某晚的计划** → 删掉 `output/plans/plan_YYYY-MM-DD.csv`
- **部分成交** → 手改那份 CSV 的 `Target_Weight`
- **跳过几天** → diff 对比上一份存在的计划；只要那期间原封不动持有就是对的

这比之前的版本更重要：仓位规则本身依赖它，不只是订单 diff。

### 模型层 — 按头特征策略

三种筛选器都做过完整对照(每折只用自己的训练窗口,与拟合同等防泄漏),
**结论是按头分治**,在 `models.HEADS` 里各自声明:

| 头 | 策略 | wf_step=40 对照依据 |
|---|---|---|
| `selection` | **策展池 + 不筛**(305 − 69 个新增 A/B/D/F 族 = 236 特征直入) | 池 +0.037 > 158 基线 +0.031;IC 筛选 −0.005、Lasso +0.018 都是**负贡献** |
| `timing` | IC 筛选(阈值 0.03,保底 top-30) | IC Brier 0.268 < Lasso 0.279 |
| `range_high` | IC 筛选 | IC pinball 0.01018 < Lasso 0.01036 |
| `range_low` | IC 筛选 | IC pinball 0.00767 < Lasso 0.00839 |

**为什么 selection 不能筛**:LightGBM 的 `colsample` 依赖特征冗余——相关特征块让每棵树
都能摸到同一信号的某个变体。单变量 IC 留下整块波动率特征(挤掉 alpha),L1 路径则把
冗余消灭得太干净,两者都伤排序。真正有效的是**族级消融**:新增的 C 形态/E 振荡/
G 主动买卖/H 衍生品/横截面/日历族单独加入都优于基线(+0.033~+0.041),
A 动量/B 波动/D 趋势/F 量能族则拖累(+0.012~+0.029),于是只排除后者
（`factors.SELECTION_EXCLUDE`，69 个）。

配置项:`FEATURE_SELECTOR=None` 表示各头用自己的默认;设成 `'lasso'/'ic'/'off'`
可全局覆盖做实验。`IC_THRESHOLD=0.03`、`IC_MIN_FEATURES=30`、
`LASSO_MAX_FEATURES=100`、`LASSO_L1_RATIO=0.9`。

**过拟合警示**:族的取舍是在同一段验证历史上决定的。族级(9 个自由度)比逐特征
(305 个)稳健得多,且各族 t 值都在 2.5~5.6,但这仍是一次「用验证集做的选择」——
新数据上跑几个月、RankIC 不掉,结论才算坐实。

### 模型层 — `LGB_PARAMS` 与按头调参

超参基线在 `LGB_PARAMS`，按头覆盖在 `HEAD_PARAMS`（由 `main.py tune` 的随机搜索
产生：每个 trial 跑一次完整的 embargo walk-forward，selection 按 RankIC、timing 按
**Brier**、range 按 pinball 选优，wf_step=40 粗筛后在 wf_step=10 复核）。

2026-09-21 的调参结果（20 trials/头，wf_step=40，各头在**最终特征策略下**重调）：

| 头 | 指标 | LGB_PARAMS 基线 | 调优后 | 采纳的覆盖项 |
|---|---|---|---|---|
| selection | RankIC | +0.0369 | **+0.0417** | `450 树, lr=0.02, leaves=63, depth=8, mcs=30, subsample=0.7, α=1.0` |
| timing | Brier | 0.2632 | **0.2561** | `leaves=15, depth=4, mcs=150, colsample=0.2, α=1.0, λ=0.5` |
| range_high | pinball | 0.0103 | **0.0102** | `leaves=15, depth=4, mcs=100, subsample=0.7, colsample=0.3, α=0.3, λ=3.0` |
| range_low | pinball | 0.0078 | **0.0077** | `leaves=15, depth=8, mcs=100, subsample=0.9, colsample=0.3, λ=3.0` |

注意两点：selection 采纳的是高容量配置（63 叶、mcs=30），+0.005 的改善在 top-5
trial 的散布（0.040~0.042）边缘，别指望全部兑现；timing 的调参目标是 **Brier 而非
AUC**——这个头的职责是诚实概率，按 AUC 选优会拿校准换它几乎没有的排序能力。

| 参数 | 默认 | 怎么调 |
|---|---|---|
| `min_child_samples` | 50 | **305 个特征下最主要的过拟合刹车。** 调高（100-200）更保守；调低会让模型记住个别币的特异行为 |
| `num_leaves` | 31 | 模型容量。与 `max_depth` 联动，`num_leaves < 2^max_depth` 才有意义 |
| `max_depth` | 6 | 交互阶数上限。金融数据很少需要超过 6-8 |
| `colsample_bytree` | 0.6 | **对 305 个高度相关的因子很关键**，降低树之间的相关性（初步对照中 0.3 略好于 0.6） |
| `learning_rate` / `n_estimators` | 0.03 / 300 | 联动：lr 减半就把树数翻倍。当前组合约 0.3 秒/fit |
| `reg_alpha` / `reg_lambda` | 0.1 / 1.0 | L1/L2。特征多时可以加大 |
| `subsample` | 0.8 | 行采样，配合 `subsample_freq=1` 生效 |

### 验证层

| 参数 | 默认 | 说明 |
|---|---|---|
| `TRAIN_WINDOW` | 252 | 滚动训练窗口（日）。≈1 年。调短更贴近当前状态但更噪 |
| `WF_STEP` | 10 | **只影响验证，不影响生产模型**。1=每天重训（最忠实，约 50 分钟）；10=约 6 分钟；20=约 3 分钟。出正式结论用 ≤10 |
| `embargo` | 7 / 1 | 在 `models.HEADS` 里，等于各头的标签视界。**必须 ≥ horizon，调低只会让分数虚高** |

### 策略层

| 参数 | 默认 | 说明 | 怎么调 |
|---|---|---|---|
| `N_ENSEMBLE` | 5 | selection 头的 bagging 集成规模（不同种子重训练）。boosting 没有随机森林的 OOB 性质，等价物是集成分歧度 = 每个预测的样本外不确定性 | 1 = 退回单模型；调大更稳但线性变慢 |
| `CONF_RANKING` | `'off'` | 排名分数：`'off'`=集成均值（默认），`'tstat'`=均值/分歧度，`'lcb'`=均值−分歧度。**为什么默认不用置信度排名**：tstat 的平均 RankIC 更高（+0.027 vs +0.018）、瞬时 top8 日收益也更高（+0.234% vs +0.169%），但它的**排序衰减快**——迟滞持仓很快过时、换手翻倍（0.42 vs 0.26），策略从 +132% 打到 +20%。均值排名「粘」，恰好与迟滞规则互补。分歧度本身有信息（与实际\|误差\|相关 +0.15），作为 Std7d 风险列输出 | 若改日频调仓，tstat 值得重测 |
| `MAX_ENTRIES_PER_DAY` | 3 | 每天最多新买入的币数（**卖出永不限制**——风控优先）。未满仓的空位持现金（每币固定 1/TOP_N 权重），不搞集中 | 调大回到旧行为；模型切换首日的大换仓也被平滑到多天 |
| `TOP_N` | 8 | 持仓数量 | 3-10 都在有效区间（见下表）。调低更集中、换手更高；20 以上 alpha 被稀释 |
| `EXIT_RANK_MULT` | 2 | 迟滞带：跌出 `TOP_N × 这个值` 才卖 | **默认值的关键。** 1=每日调仓（换手 0.61）；2=换手 0.26；3-4 换手更低但开始损失收益 |
| `USE_TIMING_GATE` | `False` | 是否用 P(up) 做开关 | **建议保持 False**，理由见上文。`--timing-gate` 可临时打开 |
| `PROB_THRESHOLD` | 0.50 | 闸门阈值（仅在闸门开启时生效） | — |
| `COST_BPS` | 10.0 | 单边手续费（基点） | **必须填你自己的实际费率。** Binance 永续 taker 默认 5bps，VIP/BNB 抵扣更低。不含滑点和冲击成本 |
| `ANNUALIZATION` | 365 | 年化因子 | 永续 7×24，365 是对的 |
| `CAPITAL` | 10000 | 计划本金，纯显示用 | — |

### 关键参数的实测敏感度

`TOP_N`（无迟滞，日频调仓）：

| top_n | 总收益 | Sharpe | MaxDD | 换手 |
|---|---|---|---|---|
| 3 | +106.9% | +0.840 | −82.3% | 0.83 |
| 5 | +63.3% | +0.705 | −73.0% | 0.69 |
| **8** | **+105.8%** | **+0.845** | **−64.7%** | 0.61 |
| 10 | +61.8% | +0.692 | −65.2% | 0.58 |
| 15 | +36.4% | +0.576 | −67.5% | 0.48 |
| 20 | +4.1% | +0.389 | −71.1% | 0.41 |

3 和 8 都约 +106%、5 只有 +63%——**这说明格子之间的差异有相当大的噪声成分**，
不要把 top_n=8 当成"最优解"，它只是有效区间的中点。

`COST_BPS`（为什么默认用迟滞而不是日频调仓）：

| 手续费 | 迟滞 (总收益/Sharpe) | 日频调仓 |

| 2bps | +116% / +0.88 | +195% / +1.07 |
| 5bps | +104% / +0.84 | +157% / +0.99 |
| **10bps** | **+86% / +0.78** | +106% / +0.84 |
| 15bps | +69% / +0.72 | +64% / +0.70 |

  以后所有 selection 的结论都以 wf10 为准。
- 资金费仍是净收入（−4.80%）。

### 集成 + 限买实验（2026-09-21，wf10 重放消融）

selection 头换成 5 模型 bagging 集成后（同规格不同种子，分歧度 = 每个预测的
样本外不确定性），三种排名 × 两种进场规则的完整消融：

```
排名        规则              总收益   Sharpe   换手   资金费
均值        旧迟滞(无限买)    +121.4%   0.89    0.26   -3.53%
均值        限买3/天+现金坡  +132.0%   0.92    0.25   -3.45%   ← 新默认
t-stat置信度 旧迟滞           +14.2%   0.46    0.45   -0.13%
t-stat置信度 限买3/天          +20.4%   0.49    0.42   -0.37%
LCB         限买3/天          +73.7%   0.74    0.26   -3.19%
```

三个结论：

- **每天限买 3 个 + 空位持现金：纯改善**，三种排名下都略赚，且把模型切换日的
  一次性大换仓摊到多天。采纳。
- **集成本身有价值**：单模型 +0.0212 的 RankIC 里有种子运气（5 种子平均后
  +0.0184），集成挤掉了这部分虚高；分歧度与实际预测误差相关 +0.15，作为
  `Std7d` 列输出到预测表。
- **置信度排名（t-stat）在模型层赢、在策略层输**：平均 RankIC +0.0269 (t=3.68)
  优于均值的 +0.0184 (t=2.13)，瞬时 top8 日收益也更高——但它的排序不「粘」，
  迟滞持仓快速过时、换手翻倍、资金费收入归零，策略 +20% vs +132%。
  均值排名稳定，与迟滞规则互补。`CONF_RANKING='tstat'` 保留为开关，
  若将来改日频调仓值得重测。

### 多空对冲实验（2026-09-21，做多 top8 / 做空 bottom8）

`rule_long_short`：每边等权、美元中性，迟滞对称作用于两边。同一份 wf10 信号：

```
                          Total Return  Sharpe  Ann.Vol   MaxDD   资金费
Selection + Hysteresis        +176.2%   +1.03    78.4%  -56.5%   -4.80%   ← 只做多
L/S 50-50 + Hysteresis         -28.6%   -0.42    29.4%  -52.7%   +0.72%
L/S 50-50 (daily)              -56.0%   -1.24    29.2%  -62.7%   +1.86%
L/S 100-100 + Hyst.            -57.3%   -0.42    58.8%  -79.7%   +1.43%
```

**结论：不做空。** 对冲在机械上是成立的（波动从 78% 降到 29%），但空头腿没有
alpha——诊断显示 bottom8 组合按做多口径日均 **+0.25%**、两年累计 **+233%**，
跑赢了等权基准：排名垫底的币不但没跌，涨得比平均还多。selection 信号的优势在
**右尾**（识别会暴涨的币），对左尾（会跌的币）没有识别力，做空 bottom 等于
做空高波动小市值的正偏度，每一次垫底币的暴涨都由空头腿全额买单。
资金费方向也和直觉相反：bottom 币的资金费偏负（做空它们要**付**资金费）。

两个必要的限定：① 幸存者偏差在这里**双重打击空头回测**——币种池按今天的成交量
选定，真正跌死退市的币（本应是最赚钱的空头）根本不在样本里，bottom8 的 +233%
被系统性高估，真实世界的空头腿不会这么惨,但差距无法用现有数据量化；
② 要真想用空头，需要专门的做空信号（如高资金费+高基差+破位的组合），
而不是把选多信号倒过来用。

## 已知局限

1. **幸存者偏差**：币种池是按**今天**的成交量选的，再回测两年。当时不火的币没进来，
   死掉的币也没进来。这会系统性抬高回测收益，幅度难以量化但**一定为正**。
   真正的修法是按每个时点的历史成交量重建池子——目前没做。

2. **回测不含滑点和冲击成本**，只有线性手续费。默认策略换手 0.26/天，
   小市值币（ONEUSDT、ZILUSDT、CELRUSDT 这类）的实际滑点可能远超 10bps。
   上表的 `COST_BPS` 敏感度就是给这个用的。

3. **只做多、不加杠杆、永远满仓**。没有整体仓位控制、没有风险预算、没有止损。
   做空已实验过（见[多空对冲实验](#多空对冲实验2026-09-21做多-top8--做空-bottom8)）：
   把选多信号倒过来做空 bottom8 是净亏损的，维持只做多。

4. **样本短**：739 个回测日 ≈ 2 年，横跨的市场状态有限。

5. **参数扫描会过拟合**：README 里的 top_n 和 cost 敏感度表是在同一段历史上跑的。
   top_n=3 和 8 都是 +106%、5 只有 +63%，这个非单调性本身就说明噪声很大。

6. **7 日标签重叠**已用 embargo 处理，但相邻行仍高度相关，有效样本量远小于 30,094 行——
   RankIC 的 t 值因此**偏乐观**。

7. **价格区间是 80% 区间**（q10–q90），校准在样本内命中，但覆盖率会随波动状态漂移。
   它不是止损位，回测里从未执行过。

8. **模型每晚覆盖 joblib 文件**，没有版本管理，无法回溯某天用的是哪个模型。

9. **持仓量/多空比因子还没进模型**（只有 30 天历史，见双轨说明）。

## 故障排查

**`BinanceError: No symbol downloaded successfully`**
限流或网络问题。缓存完好。等一小时重跑。

**部分币在下载末尾被列为 skipped**
历史不足 `MIN_HISTORY_DAYS`（新上市），正常，其余币不受影响。

**`FileNotFoundError: No Binance cache at data/binance`**
先跑 `python3 main.py download`。

**`FileNotFoundError: No trained 'selection' model`**
先跑 `python3 main.py full`（或 `backtest`）。

**`KeyError: Snapshot missing N features for head ...`**
因子层改过但没重训。跑一次 `main.py full`（或 `backtest`）重训四个头。
注：IC 筛选后各头的特征子集本来就不同，这是正常的，不是错误。

**`Range calibration: not calibrated (run backtest)`**
只跑过 `nightly` 没跑过 `backtest`。价格区间会偏窄约 5 个百分点。跑一次 `backtest`。

**as-of 日期比预期早一天**
你在 UTC 午夜前跑的，当天 bar 未收盘被自动剔除。等到 UTC 00:15 之后。

**订单看起来不对**
检查 `output/plans/` 上一份计划是否反映真实持仓。迟滞规则是路径依赖的，
见 [关键前提](#关键前提计划文件代表你的真实持仓)。
